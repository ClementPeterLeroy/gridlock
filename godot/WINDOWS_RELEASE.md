# Gridlock v3.0-beta.2 - Windows release

The game implementation and export configuration are ready for release validation.
**No Windows executable or playable ZIP was produced here:** the installed Godot
4.7.2 lacks its matching Windows export templates. The attempted executable export
reported missing `windows_debug_x86_64.exe` and `windows_release_x86_64.exe`.
Installing templates is still required before public distribution.

## Build locally

1. Open `godot/project.godot` in Godot **4.7.2** and let resources import. Existing
   Blender sources are development assets; gameplay scenes use the bundled GLBs.
2. Open **Editor > Manage Export Templates** and install the matching templates.
3. From the repository root, run PowerShell with your installed console executable:

   ```powershell
   & ./godot/tools/export_windows.ps1 -Godot 'C:/path/to/Godot_v4.7.2-stable_win64_console.exe'
   ```

The helper uses the checked-in **Windows Desktop** x86-64 release preset, generates
the actual engine's complete license notices, copies font notices and the player
README, then creates:

```text
dist/
  gridlock-v3.0-beta.2-windows/
    Gridlock.exe
    Gridlock.pck
    ...any required export companion files...
    README.txt
    THIRD_PARTY_NOTICES.txt
    GODOT_COPYRIGHT.txt
    Cinzel-OFL.txt
    Lato-OFL.txt
    LICENSE (only if present at repository root)
  gridlock-v3.0-beta.2-windows.zip
```

Keep the companion PCK with the executable; this preset does **not** embed it.
Distribute every companion file generated by Godot. The export excludes tests,
Blender source files and developer tools; the game needs neither Python, the Godot
editor nor a source checkout. Original resources, including dynamically loaded
audio/victory/intro/font assets, are included through `all_resources` export.
No blanket game license is added. Existing asset notices are retained.

For a direct export without ZIP assembly:

```powershell
godot --headless --path godot --export-release "Windows Desktop" ../dist/gridlock-v3.0-beta.2-windows/Gridlock.exe
```

For asset-pack verification without export templates:

```powershell
godot --headless --path godot --export-pack "Windows Desktop" ../dist/verification/Gridlock.pck
```

Create the target directories first. A PCK is not an executable distribution.
See Godot's [Windows export documentation](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_windows.html).

## Verification performed

- Godot 4.7.2: 10140 checks across all nine runners passed, including 12 complete
  AI matches and 525 new release checks. All three Classic parity generators pass
  `--check`; all 100 Pygame tests pass on Python 3.13.12 / Pygame 2.6.1.
- Real D3D12/Forward+ captures cover Main Menu, all four setups, How to Play,
  Settings, Game, Pause and Victory at 1280x720, 1366x768, 1600x900, 1920x1080
  and 2560x1440 (native fullscreen at the largest size), with all UI scales.
- The official intro completed automatically; no Skip is provided. Missing/corrupt
  media recovery and input blocking are covered. Native exclusive fullscreen,
  borderless fullscreen, windowed changes and timeout rollback were exercised.
  All nine application settings survived a separate-process reload; native scaled
  pawn clicks and wall targeting passed in all camera views.
- Resource-pack generation succeeds without Windows templates. Its contents exclude
  tests/development sources and include runtime models, textures, audio, branding,
  converted intro, fonts and licenses. A pack smoke check is distinct from running
  a generated Windows executable. The pack launched outside the project directory
  using the installed engine, completed the intro, started human Versus, loaded
  models/audio/fonts and exited cleanly.
- Certificate-store and global editor/user-data warnings occur in this restricted
  environment. Negative tests deliberately emit corrupt-video and invalid-match
  diagnostics. No successful executable launch is claimed.

## Manual release gate

1. Launch and watch the complete intro; return to Main Menu and confirm it does not replay.
2. Open Versus: two human names, no AI controls, no timer; start and finish a match.
3. Start Blitz against AI, Battle Royale with multiple AI, and Rise of the Machines.
4. Exercise both Blitz timer types, including original Per Game wall penalties/overtime.
5. Exercise both Battle Royale timer types and elimination with placed walls retained.
6. In Settings, change Windowed resolution; test Keep, Revert and ten-second expiry.
7. Test Fullscreen and Borderless Fullscreen, Escape rollback, minimization and recovery.
8. At 1280x720, open every menu/dropdown: no scrolling, clipping or inaccessible actions.
9. Repeat at 1920x1080, your native resolution and each UI scale; check scaled pointer
   targeting, HUD, camera views and twelve-character player/winner names.
10. Pause/settings during AI work and low clocks; resume, restart and Play Again.
11. Close/reopen: volumes, camera, animation, confirmed display and per-mode choices persist.
12. Disconnect/change a monitor or load an unsupported saved resolution; verify safe fitting.
13. Open How to Play; verify the explanations against an actual jumping/wall situation.
14. Build the Windows package, extract it elsewhere and launch independently of the editor,
    Python, and the source project, preferably on a clean Windows account/machine.
15. Verify intro, logo/icon (window/taskbar/file), all models, fonts, sounds and music;
    check mute sliders, repeated restarts and clean exit without hanging AI/audio.
16. Check drivers, unsigned-build/SmartScreen handling, companion DLL requirements and
    applicable asset notices before public upload. Signing is not configured here.

Audio remains placeholder material. An exempt AI with no legal action can still
stall; no new pass/draw rule is introduced. Smaller desktops get a fitted fallback
but are outside the official 1280x720 minimum. The graphical overhaul remains deferred.
