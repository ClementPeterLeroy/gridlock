VERSION 3.0-alpha.1 - 3D Foundations
Completion date: 2026-10-28 (existing foundations commit 207706a)
Status: Completed

Features
- Added the Godot 4 3D prototype with Blender-designed board, tile, pawn, and wall
  exports, a wooden board/frame, four player-colored pawns, and a demonstration wall.

VERSION 3.0-alpha.2.1 - Core Game Engine
Completion date: 2026-10-28
Status: Completed

Features
- Added five scene-independent RefCounted core modules for match configuration,
  state/snapshots, validated actions, Classic rules, and BFS pathfinding.
- Preserved the 9 x 9 board, stable Sapphire/Crimson/Emerald/Violet IDs and goals,
  two/four-player starts, wall inventories, and clockwise 0 -> 2 -> 1 -> 3 order.
- Ported orthogonal moves, single-pawn jumps, blocked/occupied-landing sidesteps,
  four-player occupancy, and exact wall overlap/crossing/path-preservation checks.
- Added move/wall legal-action queries, structured results with stable reason
  codes, turn advancement, goal victories, and legacy forfeit/elimination transitions.
- Added deep snapshots, undo, configuration-preserving restart, deterministic
  random-source injection, and stored controller/name/future-timer configuration.
- Added a dependency-free headless runner and generated Python parity fixtures.
- Updated root/Godot documentation and synchronized the project version.

Validation and fixed issues
- Godot 4.7.2 headless suite: 3353 checks passed, including 20 reference positions,
  2560 wall comparisons, BFS/move parity, and two 32-action Python match traces.
- Existing Pygame regression suite: 100 tests passed on Python 3.13.12 / Pygame 2.6.1.
- Rejected actions preserve state/history; snapshot/configuration copies are
  independent; eliminated seats keep stable IDs and no longer block routes.
- Corrected stale README descriptions which said no Godot project existed.
- Pygame sources/history and existing Godot scenes, cameras, models/materials are unchanged.

Known limitations
- Engine is intentionally not integrated with the 3D scenes. No mouse interaction,
  AI execution, live clocks/Blitz penalties, replay persistence, or match UI yet.
- The no-move/no-wall situation has no defined legacy pass/stalemate rule; it
  remains a running match with no legal actions pending a future rules decision.
- The Windows sandbox prints a certificate-store warning during Godot startup;
  core tests do not use networking and complete successfully.

VERSION 3.0-alpha.2.2 - Interactive Board
Completion date: 2026-10-28
Status: Completed

Features
- Connected the unchanged core engine to the 3D board. Pawn positions, placed
  walls, inventories, active player, match status, and winner come from GameState.
- Added a separate human controller for pawn selection, legal destination queries,
  groove targeting, preview rotation, and validated action submission.
- Added translucent green destination overlays and a golden active-player ring,
  retaining original tile and pawn materials and the existing model offsets.
- Added engine-validated green/red wall previews, R/right-click rotation, and
  permanent walls using the existing Blender wall model and imported materials.
- Added camera-ray pawn picking and board-plane intersection in all three views,
  including during the unchanged 0.8-second camera transitions.
- Added a basic active-player/inventory panel, one victory notification, and a
  Restart Match button / N shortcut. Esc and repeat-click deselect the pawn.
- Default board uses four local humans; the Game Inspector also supports Versus.

Bug fixes and safeguards
- Hid the demonstration wall rather than treating it as an engine-placed wall.
- Tile interiors take precedence over groove tolerance, preventing accidental
  wall placement. Off-board/HUD targets hide previews; pawn selection suppresses them.
- Rejected walls preserve inventory, history, and turn order. Successful actions
  clear selection/preview and update the scene only after engine acceptance.
- Permanent walls keep imported materials; preview overrides affect preview nodes only.

Validation
- Godot 4.7.2: 3353 core checks and 602 interaction checks passed.
- Existing Pygame regression suite: 100 tests passed on Python 3.13.12 / Pygame 2.6.1.
- Existing Python parity fixtures still match 20 reference positions, 2560 wall
  comparisons, and two 32-action match traces.
- D3D12/Forward+ render captures inspected for all three cameras, move overlays,
  the active-player ring, and a translucent wall preview.
- Core scripts, Pygame files/history, existing scenes, models, pawn/wall scripts,
  lighting, and original camera presets remain unchanged.

Known limitations and remaining tasks
- Full match menus, richer victory presentation, AI execution, live clocks/Blitz
  penalties, records/replays, and preference migration are not included.
- Groove aiming comfort and long human play sessions need manual checks at user
  display resolutions. A verification checklist is included in the Godot README.
- Existing undefined no-move/no-wall behavior and visual material audit findings
  remain documented; no new gameplay rule or material redesign was introduced.
- The sandbox emits a certificate-store warning; rendered capture also reported
  shader-cache write warnings. Rendering and automated checks completed successfully.

VERSION 3.0-alpha.2.3 - Playable Matches
Completion date: 2026-10-28
Status: Completed

Features
- Implemented Design B: compact top-right player cards with identity circles,
  names, elapsed turn times, wall icons/counts, dark rounded translucent panels,
  and a thin animated golden border for the active player.
- Added the top-left hamburger menu with Settings, Pause/Resume, Restart Match,

- Added main menu and setup for local human Versus and Battle Royale, retaining

- Added pause/resume and elapsed timers without timeouts or penalties. Incoming
  turn timers reset; inactive cards retain their previous turn's elapsed time.
- Added short pawn translation, wall settling, and golden-highlight transitions.
  State remains authoritative; input locks during transitions. Pause freezes them,
  restart/navigation cancels them, and Animations Off safely completes them.
- Reused all four Classic trophy stickers and Cinzel for one dynamic winner banner.
  Victory preserves the final board and offers exactly Play Again and Main Menu.
- Added continuous low-volume music, move/wall/victory sounds, and immediate Music
  and Sound Effects volume sliders. Reused original audio/artwork/font bytes inside
  Godot for portable imports, with font licensing and asset provenance preserved.
- Added a narrow explicit engine pause API; all existing movement and wall rules
  are unchanged. Cameras, models, materials, lighting, and Pygame files are unchanged.

Bug fixes and technical safeguards
- Removed the oversized information panel; cards and modal artwork adapt to viewport
  size while preserving the original board/camera composition.
- Stopped timers in paused/settings/menu/victory states and during input-locked
  transitions. Prevented stale animation callbacks after restart or navigation.
- Preserved victory presentation when disabling an interrupted winning animation.
- Added safe modal-page removal and audio teardown, including mixer drain on exit.
  Disabled playback on the silent Dummy backend to avoid headless playback leaks.
- Updated board regression tests for the new HUD and added match-flow tests.

Validation
- Godot 4.7.2: 3359 core checks, 602 interaction checks, and 232 match checks passed.
- Match tests include complete opening-to-victory/replay sequences for both modes,
  animation/pause interruption, real GUI input, sound-event ordering, four sticker

- Python parity fixtures still match 20 reference positions, 2560 wall comparisons,
  and two 32-action match traces. Existing Pygame suite: 100 tests passed.
- Inspected actual D3D12/Forward+ renders of compact HUD/cameras, main/setup pages,
  pause/settings, and personalized victory at 1280 x 900 and 800 x 600.

Known limitations and remaining tasks
- AI, Blitz/countdown rules, timed match setup, persistent Godot preferences,
  records/replays, broader customization, and later visual polish remain deferred.
- Music/effects remain placeholders. Wall placement uses the move recording at
  lower pitch; sound quality/volume comfort requires manual audition.
- Extended human matches, pointer comfort, and display scaling need manual checks;
  the Godot README includes a checklist. The undefined legacy no-move/no-wall
  situation remains unchanged; no pass, draw, or automatic loss was added.
- The sandbox emits the existing certificate-store warning. Headless import could
  not save global editor preferences, but project imports and verification completed.
Next milestone: 3.0-alpha.3 - Game Modes & AI

VERSION 3.0-alpha.3.1 - Rise of the Machines
Completion date: 2026-10-28
Status: Completed

Features
- Ported Classic's incremental Pathfinder to scene-independent GDScript: BFS
  route distances, immediate wins, defensive threat scoring across all surviving
  opponents, useful wall placement, inventory awareness, and racing conservation.
- Restored Casual (varied movement, fewer walls) and Challenging (full wall
  evaluation) independently for every seat in Versus and Battle Royale. Any mix
  of humans and AI is supported, including AI in the first seat and all-AI games.
- Added pause-aware, frame-budgeted main-thread search targeting 4 ms per update,
  a one-second minimum presentation delay overlapping search, and an approximately
  ten-second active search limit with legal fallback. No threads or scene queries.
- Added per-seat setup selectors, controller/difficulty card tooltips, and a
  thinking message in the existing feedback area. Compact cards, golden highlights,
  cameras, pawn/wall animations, music, effects, and victory/replay are retained.
- All AI actions use the authoritative engine's validation and existing human
  action presentation path. No gameplay rules, models, materials, or lighting changed.

Bug fixes and technical safeguards
- Search copies board data and never mutates the live state. Restart, navigation,
  exit, and victory discard pending work; pause/settings freeze search and delay.
- Position tokens detect changed turns, walls, inventories, controllers, elimination,
  restart, and undo. Clear the executed token so undo back to that exact position
  starts a fresh search instead of leaving an executed-action latch behind.
- Ignore removed pawns during opponent evaluation. Rejected proposals and the
  undefined legacy no-action situation stop retrying and show clear feedback.
- Both human and AI turns keep existing elapsed timer behavior. Countdown clocks
  and Blitz rules remain deferred; no new timeout, pass, draw, or loss rule was added.

Validation
- Godot 4.7.2: 3359 core, 602 interaction, 232 match-flow, and 1736 AI checks passed.
- AI checks cover legal proposals at both levels, every player identity, all 90
  setup combinations, immediate wins/threats, empty inventories, elimination,
  pause/settings, restart/cancellation, undo, engine rejection, mixed human/AI
  handoff, expired budgets, and no-action latching. Existing match tests preserve
  animation, audio-event, camera, victory, and responsive HUD coverage.
- Completed 12 AI matches: both modes, Casual/Challenging/mixed difficulties,
  two seeds each; 842 accepted decisions including 170 walls, all reaching victory.
- Final headless benchmark: mean decision 41.254 ms, maximum 253.033 ms, maximum
  candidate 15.359 ms, maximum frame slice 17.811 ms (wall-clock, excluding
  presentation/animation waits). A run concurrent with graphical capture recorded
  a 182.273 ms slice; OS scheduling/load affects these cooperative measurements.
- All 48 deterministic AI decisions match the unchanged Pygame Pathfinder with
  a shared random policy (no shuffle, zero noise, random=0.1). Existing core parity
  still matches 20 positions, 2560 walls, and two 32-action traces. Both Python
  fixture generators pass --check; all 100 Pygame tests pass on Python 3.13.12.
- Inspected D3D12/Forward+ captures of four-seat setup at 1280 x 900 and 800 x 600,
  the thinking HUD, and pause. Original Pygame files and previous history remain intact.

Known limitations and remaining tasks
- Search scheduling is cooperative between candidates, not a hard real-time bound.
  Individual evaluations and OS scheduling may exceed the requested frame slice.
- Runtime random sequences differ between Python's MT and Godot's PCG; identical
  numeric seeds need not produce identical matches. Deadlines can truncate searches
  at different candidates; deterministic heuristic comparisons match.
- Undefined no-move/no-wall positions remain safely latched without inventing a
  new rule. No neural network or minimax was added; neural AI remains for v3.1.
- Blitz/countdowns, broader customization, persistent Godot settings, records,
  and later visual polish remain deferred. Audio is still placeholder material.
- Long interactive play, listening comfort, and device-specific display/input
  checks remain manual; see the README checklist. The existing sandbox root-
  certificate-store warning does not prevent tests or rendered startup. Project
  import succeeds; sandbox access prevents saving global Godot editor preferences.

VERSION 3.0-alpha.3.2 - Blitz & Timers
Completion date: 2026-10-28
Status: Completed

Features
- Migrated Classic timing into the scene-independent authoritative engine:
  elapsed turns, chargeable turn time, optional 15/30/60/120-second limits,
  per-player Blitz clocks, penalties, overtime, and timeout resolution.
- Added Blitz to main-menu selection with 1/3/5-minute clocks (default three).
  Versus and Battle Royale retain Untimed by default and expose turn limits.
- Preserved the exact Blitz turn-start minimum: raise a clock below ten seconds
  to ten; leave higher clocks untouched. Never enforce the floor during a turn.
- At zero main time, lose one inventory wall and receive a fresh 15-second
  overtime for that turn. Only one penalty per turn; later turns may lose more.
  Overtime expiration or reaching zero with no walls loses immediately. Penalties
  never place or remove board walls; rejected proposals do not spend inventory.
- Standard timeout removes a pawn and skips its stable ID while keeping its walls;
  the final survivor wins. Blitz losses keep pawns, matching the Classic model.
- Compact cards read authoritative elapsed/countdown/Blitz values, label overtime,
  and use amber/red low-time feedback. Timeout victory names the losing player
  below the existing sticker. Existing identities, highlights and layout remain.

Bug fixes and technical changes
- Replaced scene-owned elapsed clocks with engine state and snapshot restoration.
  A monotonic clock adapter polls before actions, making timeout take priority at
  expiry. Simulated tick() and injectable clock sources support deterministic tests.
- Pause, Settings, animations, main-menu navigation, and victory freeze clocks.
  Restart/undo reanchor the live source to prevent stale time being charged.
- Preserved Classic's large-tick behavior: a new penalty grants a full 15 seconds
  and discards overshoot; time from an expired turn is not charged to the next seat.
- AI elapsed timers run immediately; countdowns exempt one presentation second,
  then charge only that AI's clock. Penalty/undo position changes start a fresh
  decision as in Classic. Search budgets now also respect remaining time, with
  existing incremental evaluation, pause/cancellation, and heuristics unchanged.
- Fixed stale settings-return navigation after timeout/victory and clock text
  rounding at minute boundaries. Previous tests explicitly use simulated clocks.
- Snapshot behavior follows Classic: moves, placed walls, and standard forfeits
  save clocks; automatic Blitz penalties/losses do not create extra undo entries.

Validation
- Godot 4.7.2: 3359 core, 602 interaction, 232 match-flow, 1736 AI, and 2428 timing
  checks passed. Existing AI suite completed all 12 matches (842 decisions).
- Direct Classic timing parity: 25 traces, 163 states, including all limits/clock
  choices, repeated penalties, overtime, elimination/rotation, pause/resume, undo,
  explicit AI charges, and victory freeze. No timing state or acceptance mismatch.
- Fake monotonic clocks verify timeout just before actions, goal/expiry priority,
  pause/animation freeze, restart/undo anchoring, AI exemptions and cancellation.
  Actual scene checks cover setup, low-time colors, overtime, timeout victory,
  eliminated cards, overlays, restart, and main-menu freeze.
- Existing 48 deterministic AI decisions and core Python parity remain unchanged;
  all three fixture generators pass --check. All 100 Pygame tests pass on Python
  3.13.12 / Pygame 2.6.1. No Pygame source, models, scenes, rules, camera positions,
  camera transitions, materials, lighting, or AI evaluation algorithms changed.
- Inspected D3D12/Forward+ renders: timed Battle Royale setup at 800 x 600, Blitz
  setup, overtime and timeout victory at 1280 x 900. Project startup/import succeeds.
- A rendered live-clock smoke check confirmed monotonic charging of only the
  active seat and unchanged clocks during pause.

Known limitations and remaining tasks
- The engine supports clock-restoring undo; no player-facing Undo control is added.
  Existing Godot pause-preserving undo remains intentional. Classic's larger UI
  undo grouping is not introduced in this patch.
- Broader match customization is next. Preferences remain session-only; records,
  replay storage, later visual polish and final audio remain deferred.
- AI budgets remain cooperative between candidates; OS scheduling can exceed the
  requested frame slice. No-move/no-wall positions remain undefined when untimed.
- Long interactive sessions, timing comfort and audio quality still need manual
  verification; the README includes a checklist. Existing sandbox certificate-store
  and global-editor-preference write warnings do not prevent project verification.
